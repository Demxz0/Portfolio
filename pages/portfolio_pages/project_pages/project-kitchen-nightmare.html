Kitchen Nightmare

Godot3DFirst-PersonDesign Patterns

Overview

Kitchen Nightmare is a comedic first-person cooking game made initially for a 1-month summer program at AUB's gaming academy, built in Godot 4.7 with Leen. Its plot twist is that all ingredients actively sabotage, gaslight, and ragebait you while you cook. It's still ongoing past the program month.

Origin

The idea at first was making a game that has a character with AI behavior tied to an SLM but we didn't find a suitable 2D concept. Then, we went for a low-poly 3D cooking game instead. Leen suggested the cooking gameplay; I suggested the sabotage/gaslight concept.

My Role and Responsibilities

All game logic and architecture. Leen handled assets, kitchen scene building, and later sound/UI/transition polish , I helped her through 3D issues since it was her first time (lighting, prefabs, walls, floor).

Process & Breakdown

I set up the repo and base code while Leen wrote the GDD. Before writing any gameplay code, I set 4 architecture rules: composition over inheritance, data-driven logic, signal/event bus decoupling, and one reusable state machine. I wrote these into a rules file inside the project for Antigravity IDE to follow.

The base code was the data-driven and autoload scripts: levels, ingredients, recipes, state machine, event bus, level/game/phase managers. Then i made interaction logic and worked on first-person pickup/release logic. I generalized some scripts the AI was trying to make a script for each thing with same logic like cabinets and fridges (one script for open behavior, not one per object). After that i made station scripts: gathering, cutting board, stove, assembling (refactor it so all station take from one station class). Made only 3 levels as a prototype only, level 0 as a tutorial introducing the "sneaky egg and bread" ragebait letting the player know what kind of game this is.

Challenges and Problems Solved

  • Held items clipped through anything in front of the player, so I researched the problem and found a known solution for every first person game. A second camera rendering only the held item.
  • Assembling ingredients into a pot/plate needed unique placement per ingredient per recipe — AI suggested storing coordinates on the ingredient data, which didn't work; i solved the problem on my own by realizing that coordinates belong on the recipe data instead.
  • Delayed the sabotage/ragebait system until near the end, which left too little time and I had to shift the final push to audio polish instead.
