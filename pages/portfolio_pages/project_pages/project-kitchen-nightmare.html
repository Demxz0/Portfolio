Kitchen Nightmare

Godot 3D FSM

Overview

Kitchen Nightmare (also called Recipe for Betrayal) is a comedic first-person cooking game made for a 1-month summer program at AUB's gaming academy, built in Godot with Leen. The twist: ingredients actively sabotage, gaslight, and ragebait you while you cook.

My Role and Responsibilities

All game logic and architecture. Leen handled assets, kitchen scene building, and later sound/UI/transition polish. I enforced strict architecture rules from day one.

Process & Breakdown

I set 4 architecture rules: composition over inheritance, data-driven logic, signal/event bus decoupling, and one reusable state machine. This formed an informal TDD (technical design document).

  • Data-driven scripts first: levels, ingredients, recipes, player skills
  • Core systems: state machine, event bus, level/game managers
  • Generalized interactable script for cabinets/fridges
  • First-person pickup/release logic
  • Prototype scope: 3 levels, level 0 as tutorial

Challenges and Problems Solved

  • Held items clipped through objects — solved with a second camera rendering only the held item.
  • Assembling ingredients needed unique placement — worked out that coordinates belonged on the recipe data, not the ingredient data.
  • Converting every prefab to a rigid body with correct collisions per state took a lot of time.

My Impact & Decisions

I achieved a fully data-driven cooking system with a working sabotage-ready architecture, delivered as a playable prototype in one month. Enforcing strict architecture rules from day one kept the codebase maintainable as scope grew.

Lessons Learned

  • Learned to design architecture before writing gameplay code
  • Core mechanics should be built early, not delayed (sabotage was added late)
  • AI-generated code needs active correction toward reusable patterns
  • Some problems need your own reasoning, not just AI suggestions
