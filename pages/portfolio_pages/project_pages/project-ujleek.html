Ujleek

Unity React Web
Scroll

Overview

Ujleek is an educational web platform for Gen Z about common mental disorders, built as my graduation project with a team of 5 over 2.5 months. It combines a written platform with an interactive web game, aimed at making mental health information short, easy to digest, and Gen-Z-friendly.

My Role and Responsibilities

Team lead. Planned the site structure and content architecture, ran Scrum sprints in Jira, taught teammates unfamiliar with GitHub/Jira, ran planning meetings, and built the Unity game myself.

Part 1 — The Website

I built the site's structure and content layout; the dev team built to the design and added disorder pages and screening quizzes. I fixed critical issues like exposed API keys by building a backend, and stepped in to make the entire site responsive in one pass using an AI coding agent.

Redesign: After the initial build, we redid the main page with better UX, moving the nav bar, adding smooth scrolling, a nostalgia image slider, and improving the layout of disorder pages.

Part 2 — The Game

A 3D low-poly prototype focused on Anxiety disorder. Set in a house to show that disorders are carried everywhere, including home. It features a breathing UI, a limited medicine system (3 pills with visual costs to emphasize breathing as a better long-term tool), and three rooms focusing on Attachment Anxiety, Social Anxiety, and Agoraphobia.

Used color theory (orange for anxiety, blue for closure) and custom voice acting.

Challenges and Problems Solved

  • Team lacked GitHub/Jira experience, required teaching tools mid-project.
  • First time building a full 3D scene — real-time lighting issues forced me to scale down the house.
  • Performance problems with WebGL forced us to drop the browser goal for the game entirely due to time constraints.

Lessons Learned

  • Web: train your team on tools early, don't skip references before committing to a design, scope mobile support deliberately.
  • Game: for browser-based games, go 2D — real-time 3D lighting causes major web-export problems.
  • Don't scope voice-heavy content without a realistic plan for recording it.
  • Watch code architecture early; small late-stage fixes cascading into new bugs is a sign it's too fragile.
